Sales & Purchase Forecasting — Technical Reference

This document is a developer-facing specification of how the Forecasting module computes its numbers and how it talks to the OpenAI LLM. It is a static snapshot: all worked figures below were computed once (offline) from the live dataset and pasted here; the page does NOT call the model. This file is not linked anywhere in the application and is not served by Django.

0. Scope & snapshot

  • Company (locked): Testing_Plastic_comp — companydata.id = 548. Forecasting is enabled only for this company (constant FORECAST_COMPANY_ID = '548').
  • Data span: Apr-2023 → Sep-2026 (42 monthly points). Last actual month = Sep-2026.
  • Snapshot date of the figures below: 2026-09-30.
  • Two sides: Sales (invoice doc_type Invoice) and Purchase (invoice doc_type Purchase Invoice).
  • Two measures: Revenue/Expenditure (sum of line Amount, ₹) and Product quantity (sum of line quantity, units).
  • Two granularities: Monthly and Yearly (Indian fiscal year, Apr–Mar).

1. Method names (for documentation)

  1. Primary — LLM-based (zero-shot) time-series forecasting, model OpenAI gpt-4.1-mini, called through the Chat Completions API. The model extrapolates trend and seasonality from the supplied monthly history. Used only when OPENAI_API_KEY is configured.
  2. Fallback — Seasonal Naïve (SNaïve) with year-over-year growth adjustment (a seasonal-naïve forecast scaled by a multiplicative YoY growth factor). Deterministic; used when no API key is set or the model call fails / returns unparseable JSON.

2. Data source & aggregation

All series are built from invoice.InvoiceData line items joined to their parent invoice.Invoice, scoped to the company by the parent's Seller_data (which stores the owning company id). The month bucket is taken from the parent Invoice_date.

Seriesdoc_typeField summedBucket

For product forecasting, only the top 6 products by total quantity are forecast (FORECAST_TOP_PRODUCTS = 6).

3. The statistical (fallback) formula

Let S[y,m] be the monthly series (revenue or product qty).

YoY growth factor:
    g = ( sum of the last 12 months )  /  ( sum of the previous 12 months )
    g is clamped to the range [0.5, 2.0]
    (if fewer than 24 months of history, g = 1.0)

Monthly forecast for a future month (y, m):
    baseline = S[y-1, m]                    # same calendar month, one year earlier
                                            # (if that month is itself a forecast,
                                            #  the already-forecast value is used;
                                            #  if entirely missing, the mean of the
                                            #  last 3 available months is used)
    forecast[y, m] = max( baseline * g , 0 )

Fiscal-year (Apr-Mar) total:
    FY(f) = sum over the 12 months Apr(f) .. Mar(f+1) of:
                actual value if the month is known, else the monthly forecast

The LLM path replaces only the "monthly forecast" step: instead of baseline * g, the model returns each future month's value directly. The YoY growth figure is still computed and shown for reference in the UI, and the fiscal-year aggregation is identical for both paths.

}

The server parses choices[0].message.content as JSON, maps each "Mon-YY" label back to its (year, month) key, coerces to a non-negative number, and if any series/month is missing or unparseable it discards the whole LLM result and uses the statistical fallback instead.

7. Source code (verbatim)

7.1 Series aggregation — _forecast_series_data

def _forecast_series_data(company_id, doc_type='Invoice'):
    """Monthly amount {(y,m): amount} and per-product monthly qty
    {product: {(y,m): qty}} from invoice lines of the given doc_type
    ('Invoice' = sales, 'Purchase Invoice' = purchase)."""
    lines = InvoiceData.objects.filter(
        doc_type=doc_type, Invoice_data__Seller_data=str(company_id)
    ).values_list('Products', 'Amount', 'quantity', 'Invoice_data__Invoice_date')
    revenue = defaultdict(float)
    product = defaultdict(lambda: defaultdict(float))
    totals = defaultdict(float)
    for name, amount, qty, idate in lines:
        if not idate:
            continue
        ym = (idate.year, idate.month)
        revenue[ym] += _to_number(amount) or 0.0
        pname = (name or '').strip()
        if pname:
            q = _to_number(qty) or 0.0
            product[pname][ym] += q
            totals[pname] += q
    return revenue, product, totals

7.2 Year-over-year growth — _series_growth

def _series_growth(series):
    """Year-over-year growth = last 12 periods total / previous 12 periods total.
    Returns (growth, last12_total, prev12_total)."""
    vals = [series[k] for k in sorted(series)]
    if len(vals) >= 24 and sum(vals[-24:-12]) > 0:
        cur, prev = sum(vals[-12:]), sum(vals[-24:-12])
        return min(max(cur / prev, 0.5), 2.0), cur, prev
    return 1.0, (sum(vals[-12:]) if vals else 0.0), 0.0

7.3 Statistical fallback — _stat_forecast

def _stat_forecast(series, future_keys):
    """Seasonal-with-growth fallback: each future month = the same calendar month
    a year earlier (actual or already-forecast) scaled by recent YoY growth."""
    past = sorted(series)
    vals = [series[k] for k in past]
    growth = 1.0
    if len(vals) >= 24 and sum(vals[-24:-12]) > 0:
        growth = min(max(sum(vals[-12:]) / sum(vals[-24:-12]), 0.5), 2.0)
    recent = (sum(vals[-3:]) / len(vals[-3:])) if vals else 0.0
    out = {}
    combined = dict(series)
    for (y, m) in future_keys:
        base = combined.get((y - 1, m))
        if base is None:
            base = recent
        val = max(base * growth, 0.0)
        out[(y, m)] = val
        combined[(y, m)] = val
    return out

7.4 LLM call + response parsing — _openai_forecast

def _openai_forecast(series_map, past_keys, future_keys):
    """Ask OpenAI to forecast each named series over future_keys. Returns
    {name: {(y,m): value}} or None if unavailable/unparseable."""
    api_key = getattr(settings, 'OPENAI_API_KEY', '')
    if not api_key:
        return None
    past_labels = [_month_label(*k) for k in past_keys]
    future_labels = [_month_label(*k) for k in future_keys]
    hist = {name: {_month_label(*k): round(series.get(k, 0.0))
                   for k in past_keys}
            for name, series in series_map.items()}
    system = (
        "You are a demand-forecasting engine. Given monthly historical values, "
        "forecast the requested future months using trend and seasonality. "
        "Return ONLY JSON of the form "
        '{"<series name>": {"<Mon-YY>": <number>, ...}, ...} with a value for '
        "every requested future month and every series. Numbers only, no text."
    )
    user = (
        f"History (last {len(past_labels)} months): {json.dumps(hist)}\n"
        f"Forecast these future months for every series: {future_labels}"
    )
    body = json.dumps({
        'model': getattr(settings, 'OPENAI_MODEL', 'gpt-4.1-mini'),
        'messages': [
            {'role': 'system', 'content': system},
            {'role': 'user', 'content': user},
        ],
        'temperature': 0.2,
        'response_format': {'type': 'json_object'},
    }).encode('utf-8')
    req = urllib.request.Request(
        OPENAI_URL, data=body,
        headers={'Authorization': f'Bearer {api_key}', 'Content-Type': 'application/json'},
    )
    try:
        with urllib.request.urlopen(req, timeout=30) as resp:
            data = json.loads(resp.read().decode('utf-8'))
        parsed = json.loads(data['choices'][0]['message']['content'])
    except (urllib.error.URLError, KeyError, ValueError, TimeoutError):
        return None
    label_to_key = {_month_label(*k): k for k in future_keys}
    out = {}
    for name in series_map:
        per = parsed.get(name) or {}
        if not isinstance(per, dict):
            return None
        out[name] = {}
        for lbl, key in label_to_key.items():
            v = _to_number(per.get(lbl))
            out[name][key] = max(v, 0.0) if v is not None else None
    return out

7.5 Orchestration (how a request selects LLM vs fallback)

# 1. Build the monthly series for the requested side (doc_type) and company 548.
revenue, product, totals = _forecast_series_data(company_id, doc_type=doc_type)

# 2. Choose series to forecast: {'revenue': ...} or top-6 products.
# 3. Try the LLM over the requested future months:
ai = _openai_forecast(series_map, past_keys, future_months)   # None if no key / failure
used_ai = ai is not None

# 4. Per series: use the LLM values, else the statistical fallback.
for name, series in series_map.items():
    fc = ai.get(name) if ai else None
    if not fc or any(v is None for v in fc.values()):
        fc = _stat_forecast(series, future_months)
    forecasts[name] = fc

#    12 months of each fiscal year (actual where known, forecast otherwise).

8. Notes / assumptions

  • Fiscal year is Indian (Apr–Mar). "FY 2026-27" = Apr-2026 … Mar-2027.
  • The growth factor is intentionally clamped to [0.5, 2.0] to stop a single anomalous year from producing extreme forecasts.
  • When the same calendar month one year earlier is itself a forecast (e.g. forecasting 13–24 months out), that forecast value becomes the next baseline — so growth compounds year over year.
  • Currency is shown as ₹ Lakh / Crore in the UI; raw values are plain rupees.
  • All numbers in sections 4 and 5 are a static snapshot (data through Sep-2026, computed 2026-09-30). Re-run the offline computation to refresh them.
