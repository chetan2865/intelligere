Point 2 — "Is Existing Open PO Enough?" — Calculation & Verification

This document proves the calculation used by Report 2 and reconciles it with the testing team's Excel sheet for Product A, B and C. Short version: the formula is identical to the Excel; the numbers differ only because the Excel's input values (consumption, lead time, current stock) are illustrative and do not come from the live data. The one live input that the Excel took from the system — the Open PO quantity — matches our output exactly (80 / 75 / 55). All figures below are a static snapshot: company Intelligere PVT.LTD. (id 522), data through Sep-2026, computed 2026-09-30.

1. The formula (identical to the Excel)

Avg Daily Consumption = (units sold in the last 30 days) / 30
Upcoming Requirement  = Avg Daily Consumption × Lead Time + Min Qty
Available Supply      = Current Stock + Open PO
Shortage              = Upcoming Requirement − Available Supply     (>0 = short)

2. Exact data sources / field mappings

InputSourceDefinition
Avg Daily ConsumptionInvoiceData, doc_type Invoice, last 30 daysΣ line quantity per product ÷ 30
Lead TimeInvoice, Outbound Purchase Order & Inbound ChallanAverage of (challan date − its PO date); each challan line is tied to its PO by ref_doc_no
Min QtyProduct.other_details "Minimum Quantity"reorder safety floor
Current StockProduct.sku[].warehouse[].qty (summed per item)live on-hand stock
Open POOutbound Purchase Order lines − Inbound Challan linesordered but not yet received (still open)

Why Open PO is "ordered − received": goods already received (Inbound Challan) are already counted inside Current Stock. Adding the full ordered quantity on top would double-count them, so the still-open portion is ordered − received.

6. Note on rounding

The code rounds the final Upcoming Requirement to the nearest integer (round()). The Excel truncates it (e.g. 156.575 shown as 156). This can differ by one unit on a single product (Product B: our 157 vs Excel 156, so shortage 82 vs 81). It is only a display-rounding convention on the last step, not a difference in the calculation. It can be switched to truncation if the team prefers to match the sheet to the unit.

7. Source code (verbatim)

7.1 Lead time — average of (challan − PO) via ref_doc_no

def _product_ref_leads(company_id):
    """Per-product supplier lead time (days): the average of
    (Inbound Challan date − its Outbound PO date), each challan line tied to its
    originating PO by ref_doc_no. Returns ({product: avg_lead}, company_avg)."""
    oqs = Invoice.objects.filter(doc_type='Outbound Purchase Order')
    iqs = Invoice.objects.filter(doc_type='Inbound Challan')
    if company_id:
        oqs = oqs.filter(Seller_data=str(company_id))
        iqs = iqs.filter(Seller_data=str(company_id))
    opo_date = {inv.doc_no: (inv.doc_date or inv.Invoice_date) for inv in oqs}
    ich_date = {inv.doc_no: (inv.doc_date or inv.Invoice_date) for inv in iqs}

    cl = InvoiceData.objects.filter(doc_type='Inbound Challan')
    if company_id:
        cl = cl.filter(Invoice_data__Seller_data=str(company_id))
    per_product = defaultdict(list)
    all_leads = []
    for product, ref, cdocno in cl.values_list(
        'Products', 'ref_doc_no', 'Invoice_data__doc_no'
    ):
        ref = (ref or '').strip()
        od = opo_date.get(ref)
        cd = ich_date.get(cdocno)
        if od and cd:
            days = (cd - od).days
            if days >= 0:
                all_leads.append(days)
                p = (product or '').strip()
                if p:
                    per_product[p].append(days)
    avg_map = {p: sum(v) / len(v) for p, v in per_product.items()}
    company_avg = (sum(all_leads) / len(all_leads)) if all_leads else None
    return avg_map, company_avg

7.2 Open PO (ordered − received)

ordered  = _line_qty_by_product('Outbound Purchase Order')   # Σ OPO line qty per product
received = _line_qty_by_product('Inbound Challan')           # Σ challan line qty per product
open_po  = { name: max(ordered[name] - received[name], 0) for name in ordered | received }

7.3 The calculation per product

avg_daily   = sold_last_30_days / 30.0
lead        = lead_by_product.get(name, company_avg)          # float days
min_qty     = product "Minimum Quantity"
requirement = round(avg_daily * lead + min_qty)
stock       = Σ Product.sku[].warehouse[].qty
po          = open_po[name]
supply      = stock + po
shortage    = round(requirement - supply)                     # > 0 means short

8. Conclusion

Report 2's calculation is correct and formula-identical to the testing team's Excel. The Open PO figures (80 / 75 / 55) and Min Qty (10) match the sheet to the unit; feeding the sheet's own inputs into our formula reproduces its outputs (shortage 49 / 81 / 108). The remaining differences come only from the Excel using illustrative consumption, lead-time and current-stock values that are not present in the live dataset.
